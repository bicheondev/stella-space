# STELLA SPACE

치지직의 채팅 구조와 한글 가독성을 유지하면서, “X가 채팅 팝아웃을 만들었다면?”이라는 콘셉트로 구성한 스텔라이브 Space 공유 게시물 답글 뷰어입니다. 검정 배경, 얇은 회색 구분선, 흰색 중심의 헤더와 절제된 파란색 포인트를 사용합니다.

채팅만 화면 전체에 표시하며, 본문 앞의 수신자 @멘션을 숨깁니다. 본문 중간의 멘션은 유지합니다. 하단 채팅 입력창은 없습니다. 맨 위에 멤버 선택, 채팅 헤더에 글자 확대·축소와 설정, 아래쪽에 조회 상태와 팝업 버튼을 둡니다. 공유 게시물 URL 입력과 방송 정보는 버튼을 눌렀을 때 펼쳐집니다.

## 실행

Node.js 22 이상과 curl 설치 후:

```sh
node preview.mjs
```

http://127.0.0.1:4173 에 접속합니다. 답글은 FxTwitter 공개 API에서 수집합니다.

## 답글 수집 경로

| 경로 | 테스트 결과 | 제한 |
|---|---|---|
| FxTwitter 공개 API | `/2/conversation/2112891916077687250?ranking_mode=recency`에서 직접 답글 28개 수집 | 다음 페이지 커서는 반환됐지만 실제 다음 페이지 요청은 code 404. 최신순 첫 페이지를 주기적으로 확인하는 방식 |
| Nitter | XCancel은 HTTP 451 서비스 중단, Poast는 DNS 실패 | Nitter 자체 서버 구현은 OAuth/계정 쿠키 세션 사용. 완전 비로그인 자체 수집 경로로 간주할 수 없음 |

FxTwitter의 구형 `/:handle/status/:id`는 답글 수만 반환하지만 **v2 conversation API는 답글 목록을 반환**합니다. API에 사용자 계정·유료 키를 보내지 않습니다. 다만 제공자 내부에서 X 계정 세션을 사용하는지는 보장할 수 없습니다.

분당 900회 목표 예산에서 멤버 상태 조회용 180회를 제외한 720회를 답글 수집에 배분합니다. 답글 간격은 `ceil(60000 × max(방송 중 멤버 수, 최근 30초 수집 방 수, 1) / 720)` 밀리초입니다. 모든 FxTwitter 호출은 D1의 공통 슬롯(67ms 간격, 최대 2초 대기)을 예약해 분산하며 초과 대기 시 기존 결과와 재시도 제한을 적용합니다. 각 조회 응답이 현재 간격을 반환해 화면도 같은 주기로 갱신합니다. 모든 Sites 실행 서버는 하나의 D1 데이터베이스에서 게시물·수집 경로별 잠금과 결과를 공유합니다. 잠금을 획득한 한 요청만 외부 API를 호출하며 나머지는 저장된 결과를 받습니다. 수집이 진행 중이면 기존 기록을 반환하고 첫 수집이 끝나지 않은 경우 대기 상태를 반환합니다. 성공 후 계산된 주기 동안 재수집하지 않으며, 실패 시 최소 3초·429 응답 시 30초 동안 재시도를 억제합니다. 만료된 잠금은 복구할 수 있고 이전 수집기는 새 결과를 덮어쓸 수 없습니다. 최신 500개 답글을 공유 저장하므로 새로고침·다른 서버에서도 누적 기록을 읽습니다. 화면은 일부 답글임을 표시하며, 오류 시 이전 답글을 유지하고 조회 실패를 알립니다. 답글 내용은 HTML로 실행하지 않고 텍스트로 표시합니다. 직접 답글만 포함하며 부모 글·인용 글·대댓글을 섞지 않습니다. 추가 페이지 수집 기능은 검증되지 않아 자동 실행하지 않습니다.

## 기능과 남은 한계

- 4개 기수 15명, 프로필 드롭다운. 토아 계정은 `ShizukiToa_`로 수정하고 이미지 확인 완료.
- Space 공유 게시물 URL 해석, 팝업, 시간 표시, 글자 크기, 자동 스크롤.
- Space 링크만으로는 공유 게시물 ID를 알 수 없어 답글 조회에 공유 게시물 URL 필요.
- 멤버 최근 5개 게시물에서 본인의 Space 공유 게시물을 찾고 실제 Space 메타데이터로 방송 중·종료를 확인합니다. 최근 5개에 Space 공유 글이 없으면 오프라인으로 판정합니다. 최근 공유 게시물은 5초 주기로 확인합니다. 새 Space는 발견 즉시 상태를 조회하고, 이미 방송 중인 Space 상태는 15초, 종료된 Space는 60초간 공유 캐시합니다. 선택한 멤버가 새 Space를 시작하면 공유 게시물을 자동 연결합니다. 조회 실패를 오프라인으로 표시하지 않습니다.
- 과거 Space 종료를 현재 멤버 오프라인으로 단정하지 않음.
- X 음성 자막은 답글 대신 표시하지 않음.
- 배포 사이트는 현재 소유자 전용으로 ChatGPT 로그인이 필요함. 로컬 페이지와 X 데이터 요청에는 사용자 로그인 불필요.

## Sites만으로 운영

배포 후에는 로컬 Node 서버·PC·크론을 켜 둘 필요가 없습니다. 웹페이지, 외부 API 수집, 결과 저장과 전 서버 간 수집 잠금을 모두 Sites Worker와 D1에서 처리합니다. 사이트를 보는 사람이 있을 때 요청을 계기로 수집하며 아무도 보고 있지 않으면 외부 조회를 멈춥니다. 별도의 상시 실행 작업이나 로컬 자동화는 생성하지 않습니다. D1 조회·쓰기 및 Sites 실행량은 호스팅 제공자의 할당량에 포함됩니다.

공유 저장소가 없거나 실패하면 서버별 개별 수집으로 돌아가지 않고 오류를 반환합니다. 따라서 배포 시 `d1: "DB"`와 `drizzle/` 마이그레이션을 함께 유지해야 합니다. 개발용 `preview.mjs`는 운영에 필요하지 않습니다.

종료된 Space는 저장된 답글만 반환하며 FxTwitter 답글 조회와 브라우저 답글 폴링을 중지합니다. 멤버 상태 확인은 새 Space 발견을 위해 계속합니다.

답글 수집과 화면 폴링은 요청 시작 시각을 기준으로 다음 간격을 계산합니다. 응답 시간이 주기보다 길면 중복 요청 없이 응답 직후 다음 조회를 시작합니다. 외부 API 응답 지연과 원본 갱신 주기는 별도입니다.

라이브 멤버 프로필은 보라색 링과 Space 배지를 표시합니다. 배지 SVG 원본: https://abs.twimg.com/x-web/x-web/assets/icon-spaces-fill-dkNkOItq.js (X 공개 웹 리소스).

API 수집 요청은 Workers waitUntil로 실행 수명을 유지합니다. 외부 요청 제한 시간은 10초이며, 중단된 수집 잠금은 25초 후 복구합니다. 답글 기록 크기는 메시지별 누적 크기로 제한해 반복적인 전체 직렬화를 피합니다.

멤버별 주소는 `/ShirayukiHina_`처럼 X 핸들을 사용합니다. 멤버 선택·자동 연결 후에도 이 주소를 유지합니다. 이전 쿼리 형식의 방 링크는 해석하지 않습니다. 경로는 해당 멤버의 최신 Space를 찾습니다. 팝업 옵션은 `?popup=1`입니다.

기본 주소 `/`는 멤버 상태를 확인한 뒤 드롭다운 순서상 첫 온라인 멤버로 이동합니다. 온라인 멤버가 없으면 드롭다운 맨 위의 강지를 선택합니다. 멤버별 주소와 사용자의 수동 선택은 자동 선택으로 덮어쓰지 않습니다.

현재 인원은 AudioSpaceById의 `participants.total`을 사용해 라이브 방에만 “명 참여 중”으로 표시합니다. 누적 `total_live_listeners`를 현재 인원으로 사용하지 않습니다. 방송 중 Space 메타데이터는 5초간 공유 캐시하며, 상태 갱신 시 헤더의 인원도 갱신합니다. 종료·미제공 시 인원 표시를 숨깁니다. Sites 예약은 최소 1시간 간격 제한으로 생성에 실패해 상시 조회는 보류했습니다.

기본 주소에서는 상태 조회를 기다리는 동안 강지를 즉시 표시하고, 확인 후 온라인 우선순위를 적용합니다. 미확인 상태 문구는 “확인 중”입니다.

강지(GANGZIIII)는 1기생 위에 카테고리 제목 없이 단독 표시하며 기본·전체 오프라인 시 최우선 멤버입니다.

자동 스크롤 버튼은 표시하지 않습니다. 위로 스크롤하면 따라가기를 멈추고 맨 아래로 돌아오면 재개합니다. 방을 새로 연결하면 자동 스크롤을 활성화합니다. 환영 문구는 “채팅방에 오신 것을 환영합니다!”로 통일합니다.
