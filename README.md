# STELLA SPACE

X Space 공유 게시물의 공개 답글을 채팅처럼 표시하는 스텔라이브 팬 도구입니다. 방문자의 X 로그인과 유료 X API 키는 필요하지 않습니다. 방송 시작 탐지에는 서버의 봇 전용 X 로그인 세션을 사용합니다. FxTwitter 제공자의 내부 인증 방식은 별개이며, 최신 일부 답글만 반환하므로 전체 답글 무누락을 보장하지 않습니다.

## 실행 구조

- Vercel: 정적 채팅 페이지, GitHub 로그인, 운영 콘솔, 피드백, 분석.
- Cloudflare: 개인 계정의 Worker와 단일 Durable Object가 전체 멤버 탐지·채팅 수집·푸시 수신을 담당합니다.
- 브라우저: Cloudflare에 직접 연결하여 최신 기록과 WebSocket 업데이트를 받습니다. 방문자 요청은 수집 작업을 실행하지 않습니다.
- Turso/libSQL: 기존 방송 기록과 메시지, 암호화된 연결 설정을 보관합니다. 새 메시지만 추가하고 실시간 공유 상태는 수집기 메모리에서 제공합니다.

무료 한도와 장애 복구에는 제한이 있습니다. 계정별 사용량을 확인해야 하며, 무중단이나 답글 무누락을 보장하지 않습니다. 자세한 구성·검증·복구 절차는 [Cloudflare 운영 문서](cloudflare/README.md)를 참고하세요.

## 배포

1. `npm ci`, `npm test`로 검증합니다.
2. 개인 Cloudflare 계정을 확인하고 `cloudflare/wrangler.jsonc`로 배포합니다. 회사 계정은 사용하지 않습니다.
3. Vercel Production의 `SPACELIVE_REALTIME_ORIGIN`에 Worker 주소를 설정합니다. 기존 OAuth·DB·암호화 환경변수는 유지합니다.
4. GitHub에 push한 뒤 Vercel 자동 배포의 성공을 확인합니다. 수동 배포는 자동 배포 실패 때만 사용합니다.
5. 기존 Actions 수집기를 중단한 뒤 인증된 Cloudflare `/control/start`로 단일 수집기를 시작합니다.

기존 Actions 워크플로와 레거시 수집 코드는 명시적 복구용으로만 남깁니다. 정기 스케줄은 제거하며 Cloudflare 전환 상태에서는 heartbeat가 즉시 종료됩니다. Cloudflare는 기존 DB 스키마를 사용하며 실행 중 스키마를 생성하지 않습니다. 비밀키는 Git이나 로그에 넣지 않습니다.

## 동작

멤버별 주소는 `/GANGZIIII`, `/ShirayukiHina_` 형식입니다. 기본 주소는 강지를 먼저 표시한 뒤 목록 순서상 첫 온라인 멤버로 이동합니다. 모두 오프라인이면 강지입니다. 최근 본인 게시물 5개에 Space 링크가 없으면 오프라인으로 표시합니다. 종료가 확인된 방은 답글 수집을 멈추고 기존 기록만 표시합니다.

FxTwitter 호출은 분당 900회를 목표로 공통 67ms 슬롯을 예약합니다. 15명 프로필 조회의 분당 180회를 제외한 720회가 답글 예산입니다. 답글 간격은 방 수에 비례하며 응답 시간 때문에 실제 속도는 더 느릴 수 있습니다.

상단 +/−는 글자 크기를 조절합니다. 위로 스크롤하면 따라가기를 멈추고 맨 아래에서 재개합니다. 사진은 최대 120×90px 썸네일로 표시합니다. Apple 기기는 시스템 글꼴, 나머지는 Pretendard와 JP 서브셋 및 ss05를 적용합니다.

기존 Sites용 파일은 이전 배포 참고용이며 Vercel 배포에서는 `.openai`, Sites 빌드·저장소 도구를 호출하지 않습니다.

방송 시작부터 수집한 답글은 별도 메시지 테이블에 중복 없이 누적하며 500개 제한으로 삭제하지 않습니다. 최근 200개를 먼저 표시하고 이전 기록은 커서로 백그라운드에서 읽습니다. 방종 후에는 마지막 방송을 멤버별로 유지하고, 다음 방송 시작이 확인되면 새 방송 기록으로 전환합니다. 새 Space가 예정·미확인인 동안은 이전 방송을 유지합니다. 기존의 과거 500개 캐시는 새 기록으로 옮기지만 이미 삭제된 예전 답글은 복구되지 않습니다.

## Space 상태 판정

게시물 탐색과 기존 Space의 상태 확인을 분리합니다. 기존 Running Space는 최근 5개에서 링크가 사라져도 AudioSpaceById로 개별 확인하며, 명시적인 Ended 응답으로만 수집을 종료합니다. 메타데이터 조회 실패는 unknown이고 방송 기록은 유지합니다. 기존 라이브 Space가 없는 경우 최근 5개에 링크가 없으면 offline으로 보는 규칙은 유지합니다.

타임라인은 FxTwitter 우선, 실패하면 CarryFeed로 전환합니다. 제공자별 호출 간격과 재시도 시각을 단일 수집기가 관리합니다.

구현 검토에 참고한 프로젝트:
- x-notify-dc: https://github.com/DezXBT/x-notify-dc/blob/main/poller.go — 알림함 일괄 조회 보조 경로 검토. 이 프로젝트의 notification 토픽은 실제 구독이 거절되어 사용하지 않습니다.
- Bluebird: https://github.com/EthanC/Bluebird/tree/main/core — 수집 소스 전환·실패 복구와 CarryFeed의 공개 타임라인 형식.
- Tweetcord: https://github.com/Yuuzi261/Tweetcord/blob/main/src/notification/get_tweets.py — 지속 상태·게시물 시간 기반 진행 관리. 인증 세션 경로는 사용하지 않습니다.

## 봇 Web Push

운영 페이지에서 연결한 봇 세션과 Mozilla 푸시 구독의 개인 키는 `OPERATIONS_SECRET` 기반 인증 암호화로 공유 DB에 저장합니다. 수집기 전용 인증 API만 이를 읽을 수 있고 일반 방문자나 운영 상태 응답에는 포함하지 않습니다. 등록된 멤버 15명의 팔로우·게시물 알림을 확인한 뒤, `xnotif`의 Mozilla Autopush 연결·복호화 기능으로 브라우저 알림을 받습니다. X 기기 등록 요청은 기존 X 웹 요청 서명을 사용합니다.

알림 수신 시 봇 알림함에서 게시물 내용을 확인하고 등록된 멤버의 원본 게시물만 저장하여 방송 탐지를 갱신합니다. 정상 푸시 연결 중 알림함 보조 조회는 30초, 푸시 연결 실패 시 5초입니다. 새 푸시는 도착 즉시 처리하며 이 안전 조회 주기를 기다리지 않습니다. X의 429 응답은 재시도 시각까지 기다립니다. FxTwitter·CarryFeed의 429는 제공자별 공유 중지 시각으로 모든 수집기에 적용합니다. Retry-After 및 리셋 헤더를 반영하며, 안내가 없어도 FxTwitter는 최소 30초, CarryFeed는 최소 5분 대기합니다. CarryFeed는 공유 5초 슬롯으로 직렬화합니다. 일반 실패는 30초부터 최대 5분까지 재시도 간격을 늘리고, 호출 차례 대기는 오류 이력에 추가하지 않습니다. 정상 푸시 연결 중 프로필 보조 탐색은 성공·실패와 무관하게 제공자·멤버별 최소 약 5분(멤버별 시각 분산), 알림함만 정상인 경우 60초, 두 경로 모두 비정상이면 30초 캐시를 사용합니다. 알림으로 받은 게시물은 이 간격과 무관하게 즉시 합쳐 상태를 확인합니다. 실제 멤버 알림의 전달 지연과 누락 여부는 별도 검증이 필요합니다.

겹쳐 실행되는 수집기 중 공유 DB의 단일 담당만 푸시 연결을 유지합니다. 담당 권한은 60초 유효하며 10초마다 갱신하고, 정상 종료 신호를 받으면 연결과 권한을 반납합니다. 다음 담당은 암호화된 구독을 이어받아 불필요한 X 기기 재등록을 피합니다. 연결 재시도도 권한 확인 후에만 수행합니다. 푸시 수신과 방송 종료 판정은 별개입니다. Running Space의 `AudioSpaceById` 상태는 5초 간격으로 재확인하며 명시적인 `Ended`에서 답글 조회를 중지합니다.

- xnotif (MIT): https://github.com/yutakobayashidev/xnotif

Cloudflare의 저장된 활성 상태와 알람으로 수집기를 복구합니다. Actions의 다음 수집기 예약은 레거시 복구 모드에서만 사용합니다.

### 운영 경로 디버깅과 무료 사용량

`/ops/debug`의 URL 테스트는 실행 위치를 선택하지 않는다. 등록된 방송은 실제 운영 수집 기록을 읽고, 외부 Space는 같은 `createCollector`와 Cloudflare→Vercel 답글 경로를 사용한다. 외부 테스트 데이터는 기존 coordinator의 `debug_*` SQLite 테이블에만 저장되며, 운영 세션·Turso 채팅·웹훅에 섞이지 않는다. 별도 상시 실행 Durable Object는 만들지 않는다. 외부 테스트는 15분에 자동 종료되며, 화면 조회는 최소 1초 간격이다. 운영 WebSocket 전송 지연을 완전히 재현하는 시험은 아니다. Vercel 외부 요청은 실제 무료 사용량에 포함되지만, 테스트의 30일 1만 회 예산은 운영 답글 25만 회 예약과 분리된다.

무료 사용량 패널은 `server/usage-snapshots.json`의 날짜가 표시된 대시보드 확인값과 관리자 저장값을 표시한다. 자동 계정 사용량 API 연결은 아직 없으며, 페이지는 실시간 사용량이라고 표시하지 않는다. `/api/admin/usage` GET은 5분 캐시를 사용하고 POST는 소유자 로그인·동일 Origin을 요구한다. 서비스별 숫자 입력으로 갱신할 수 있다. Vercel은 최근 30일이므로 초기화 카운트다운을 만들지 않으며, Cloudflare는 UTC 00:00(KST 09:00) 일일 초기화와 함께 이전 날짜의 일일 확인값을 무효화한다. Turso 주기 종료는 확인된 시각을 입력한 경우에만 표시한다. 저장공간은 초기화 대상이 아니다. 미확인 수치는 0%로 표현하지 않는다.
