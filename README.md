# STELLA SPACE

치지직의 채팅 구조와 한글 가독성을 유지하면서, “X가 채팅 팝아웃을 만들었다면?”이라는 콘셉트로 구성한 스텔라이브 Space 공유 게시물 답글 뷰어입니다. 검정 배경, 얇은 회색 구분선, 흰색 중심의 헤더와 절제된 파란색 포인트를 사용합니다.

채팅만 화면 전체에 표시하며, 본문 앞의 수신자 @멘션을 숨깁니다. 본문 중간의 멘션은 유지합니다. 하단 채팅 입력창은 없습니다. 맨 위에 멤버 선택, 채팅 헤더에 글자 확대·축소와 설정, 아래쪽에 조회 상태와 팝업 버튼을 둡니다. 공유 게시물 URL 입력과 방송 정보는 버튼을 눌렀을 때 펼쳐집니다.

## 실행

Node.js 22 이상과 curl 설치 후:

```sh
node preview.mjs
```

http://127.0.0.1:4173 에 접속합니다. 설정(⚙)에서 수집 경로를 선택할 수 있습니다.

## 답글 수집 경로

| 경로 | 테스트 결과 | 제한 |
|---|---|---|
| X 공개 페이지 직접 조회 (기본) | 비로그인 HTML의 hydration 데이터에서 직접 답글 3개 추출 | 일부 인기 답글만 보일 수 있음. `sort_replies=recency`가 요청에 반영돼도 테스트 결과 목록은 같았음. 전체·실시간 수집 보장 없음 |
| FxTwitter 공개 API (선택) | `/2/conversation/2112891916077687250?ranking_mode=recency`에서 직접 답글 28개 수집 | 다음 페이지 커서는 반환됐지만 실제 다음 페이지 요청은 code 404. 최신순 첫 페이지를 주기적으로 확인하는 방식 |
| Nitter | XCancel은 HTTP 451 서비스 중단, Poast는 DNS 실패 | Nitter 자체 서버 구현은 OAuth/계정 쿠키 세션 사용. 완전 비로그인 자체 수집 경로로 간주할 수 없음 |

FxTwitter의 구형 `/:handle/status/:id`는 답글 수만 반환하지만 **v2 conversation API는 답글 목록을 반환**합니다. API에 사용자 계정·유료 키를 보내지 않습니다. 다만 제공자 내부에서 X 계정 세션을 사용하는지는 보장할 수 없습니다. 제3자 서버까지 계정 미사용 조건이라면 기본 직접 조회만 사용해야 합니다.

두 경로 모두 1초 간격으로 최신 응답을 확인합니다. 모든 Sites 실행 서버는 하나의 D1 데이터베이스에서 게시물·수집 경로별 잠금과 결과를 공유합니다. 잠금을 획득한 한 요청만 외부 API를 호출하며 나머지는 저장된 결과를 받습니다. 수집이 진행 중이면 기존 기록을 반환하고 첫 수집이 끝나지 않은 경우 대기 상태를 반환합니다. 성공 후 1초 동안 재수집하지 않으며, 실패 시 최소 3초·429 응답 시 30초 동안 재시도를 억제합니다. 만료된 잠금은 복구할 수 있고 이전 수집기는 새 결과를 덮어쓸 수 없습니다. 최신 500개 답글을 공유 저장하므로 새로고침·다른 서버에서도 누적 기록을 읽습니다. 화면은 일부 답글임을 표시하며, 오류 시 이전 답글을 유지하고 조회 실패를 알립니다. 답글 내용은 HTML로 실행하지 않고 텍스트로 표시합니다. 직접 답글만 포함하며 부모 글·인용 글·대댓글을 섞지 않습니다. 추가 페이지 수집 기능은 검증되지 않아 자동 실행하지 않습니다.

## 기능과 남은 한계

- 4개 기수 14명, 프로필 드롭다운. 토아 계정은 `ShizukiToa_`로 수정하고 이미지 확인 완료.
- Space 공유 게시물 URL 해석, 팝업, 시간 표시, 글자 크기, 자동 스크롤.
- Space 링크만으로는 공유 게시물 ID를 알 수 없어 답글 조회에 공유 게시물 URL 필요.
- 멤버 최근 20개 게시물에서 본인의 Space 공유 게시물을 찾고 실제 Space 메타데이터로 방송 중·종료를 확인합니다. 최근 공유 게시물은 5초 주기로 확인합니다. 새 Space는 발견 즉시 상태를 조회하고, 이미 방송 중인 Space 상태는 15초, 종료된 Space는 60초간 공유 캐시합니다. 선택한 멤버가 새 Space를 시작하면 공유 게시물을 자동 연결합니다. 조회 실패를 오프라인으로 표시하지 않습니다.
- 과거 Space 종료를 현재 멤버 오프라인으로 단정하지 않음.
- X 음성 자막은 답글 대신 표시하지 않음.
- 배포 사이트는 현재 소유자 전용으로 ChatGPT 로그인이 필요함. 로컬 페이지와 X 데이터 요청에는 사용자 로그인 불필요.

## Sites만으로 운영

배포 후에는 로컬 Node 서버·PC·크론을 켜 둘 필요가 없습니다. 웹페이지, 외부 API 수집, 결과 저장과 전 서버 간 수집 잠금을 모두 Sites Worker와 D1에서 처리합니다. 사이트를 보는 사람이 있을 때 요청을 계기로 수집하며 아무도 보고 있지 않으면 외부 조회를 멈춥니다. 별도의 상시 실행 작업이나 로컬 자동화는 생성하지 않습니다. D1 조회·쓰기 및 Sites 실행량은 호스팅 제공자의 할당량에 포함됩니다.

공유 저장소가 없거나 실패하면 서버별 개별 수집으로 돌아가지 않고 오류를 반환합니다. 따라서 배포 시 `d1: "DB"`와 `drizzle/` 마이그레이션을 함께 유지해야 합니다. 개발용 `preview.mjs`는 운영에 필요하지 않습니다.
